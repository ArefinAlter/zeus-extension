# Threat model: the extension slice

This is the extension's part of the security contract. The consolidated model and the numbered invariants (SI-01 and following) live in `zeus/docs/spec/12-security-invariants-and-threat-model.md`, which did not exist when this repository was scaffolded; replace the references below with SI numbers when it does. Until then each row names the test that enforces it.

## Assets

1. The user's session material (cookies, client hints, user agent for one origin).
2. The user's attention and consent: a decision attributed to a human must have been taken by a human.
3. The integrity of what the daemon commits to disk (bytes fetched through the browser).
4. The user's download history and URLs (signed URLs are bearer secrets).

## Trust boundaries

| Boundary                    | Who is on the other side             | Rule                                                                                                                                                                                                                                          |
| --------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Browser to extension        | Web pages                            | There is no channel: no content script, no `externally_connectable`, no `web_accessible_resources`.                                                                                                                                           |
| Extension to extension      | Other extensions                     | Messages are accepted only from this extension's own pages (`sender.id` and URL prefix are both checked).                                                                                                                                     |
| Extension to host           | `zeus-native-host`, `zeusd`          | The browser pins the extension to the host and the host pins the extension (spec 02 section 13.1). The daemon is the user's own installed program: a fully compromised daemon can read any lease it is given, and that is outside this model. |
| Extension to origin servers | Hostile or merely unreliable servers | Responses are data. Nothing a server sends selects a tool, a path or an approval.                                                                                                                                                             |

## Threats and mitigations

| #   | Threat                                                                                                      | Mitigation                                                                                                                                                                                                            | Enforced by (test)                                             |
| --- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| T1  | A web page triggers a cookie release                                                                        | No page-to-extension channel; release only for a daemon request that matches a consent record created by a click                                                                                                      | `consent.test.ts`, `approvals.test.ts` (foreign senders)       |
| T2  | A compromised or confused daemon asks for cookies of a site the user never approved                         | The release gate: consent record, browser-held optional host permission, never list, scheme rule                                                                                                                      | `consent.test.ts`, `session.test.ts`                           |
| T3  | A prompt-injected agent approves its own session grant                                                      | Approvals are decided only by a click in the popup (`user_gesture` captured from the browser's user-activation flag); the agent-facing API has no such operation                                                      | `approvals.test.ts`                                            |
| T4  | A hostile page floods the user with offers                                                                  | Offer rate limits (30 a minute, 5 per origin a minute), the daemon's pending-approval cap, popup coalescing                                                                                                           | `downloads.test.ts`                                            |
| T5  | Laundering of a security decision: the browser or antivirus blocked a file, the user presses "send to Zeus" | `FILE_VIRUS_INFECTED`, `FILE_BLOCKED`, `FILE_SECURITY_CHECK_FAILED`, `SERVER_CERT_PROBLEM` and Safe Browsing danger types are never offered, automatically or by the popup                                            | `downloads.test.ts`                                            |
| T6  | Cookie leakage through logs, storage or error text                                                          | Cookies exist only in the one `session.response` frame; storage holds no secret; the logger redacts URLs and logs counts only; a canary test asserts it                                                               | `session.test.ts`, `sequences.test.ts`, `events-state.test.ts` |
| T7  | A signed URL leaks through persisted state or logs                                                          | Offers are persisted without URLs (rebuilt from the browser's own item); `redact_url` vectors pass; the logger strips URLs from fields                                                                                | `downloads.test.ts`, `redact.test.ts`                          |
| T8  | Cross-origin data pull through a redirect                                                                   | Proxy fetches use `redirect: error`, refusing chains before browser cookies can reach another origin. URL refresh remains separately consent-gated.                                                                   | `fetch-proxy.test.ts`, `url-refresh.test.ts`                   |
| T9  | Replay of an old `session.request`                                                                          | A `session_id` releases material at most once; consent records expire; a failed release frees the id                                                                                                                  | `session.test.ts`                                              |
| T10 | Mislabelled bytes corrupt the daemon's file                                                                 | A `206` never exceeds its requested slice. A `200` at offset zero streams the full body under credits; a `200` at a later offset is held. The daemon validates offsets, lengths and representation before committing. | `fetch-proxy.test.ts`                                          |
| T11 | Memory exhaustion in the worker or the daemon                                                               | Credit-based flow control, bounded chunk and window sizes, at most the negotiated number of streams, length checks before allocation, a depth limit on inbound JSON                                                   | `fetch-proxy.test.ts`, `frames.test.ts`                        |
| T12 | A malformed or hostile daemon frame                                                                         | Schema validation of every inbound frame, `nm.schema_violation` replies, ten violations a minute close the connection, unknown events skipped                                                                         | `native.test.ts`, `frames.test.ts`                             |
| T13 | Spoofed notification                                                                                        | Notifications decide nothing; they carry no URL; text from remote servers is sanitised (bidirectional overrides and controls removed)                                                                                 | `approvals.test.ts`                                            |
| T14 | HTML or script injection through a file name                                                                | DOM built with `textContent` only (ESLint forbids `innerHTML`), strict CSP, no inline script or style                                                                                                                 | lint, `npm run check` (dist verification)                      |
| T15 | Supply chain: a malicious dependency in the shipped code                                                    | Only pinned `@noble/hashes` is bundled for BLAKE3; package lock committed; license included; normative hash vectors and tamper tests; `npm run check` rejects other runtime dependencies                              | `npm run check`                                                |
| T16 | Tampered or drifting contract copies                                                                        | `schema/` carries a lock file and a drift check against the zeus repository; generated types are checked for staleness                                                                                                | `npm run check`                                                |

## Residual risks

- **Same-user malware.** Anything running as the user can talk to the daemon, read the browser profile or drive the browser. The extension cannot defend against it; see the trust-surface discussion in spec 07.
- **A malicious extension with `debugger` or broad host access** can read cookies directly, without Zeus.
- **Signed-URL exposure to the daemon.** The offer necessarily carries the browser's final URL (it may be a signed bearer URL) to the local daemon; the daemon keeps it only in its owner-only journal (spec 00 section 8.2).
- **Service-worker memory.** JavaScript cannot guarantee zeroing strings; the extension keeps cookie values only for the duration of one handler and never in a persistent store.
